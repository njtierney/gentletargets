Setup

Three things before we start:

  1. How this book is put together,
  2. What to install, and
  3. What to bring.

How this book works

The book is longer than the course

The course is twelve hours of teaching. There is more in the book than we can get through, which is deliberate.

I’ll change what we cover on the day depending on how we are going, and the rest stays here for you to come back to.

How we will work

Mostly by typing.

I write code, you write it too, and we break things together.

A lot of this course is about what happens when you change your mind halfway through an analysis.

That means we’ll spend real time with things in a broken or half finished state, on purpose. If that feels uncomfortable, good, because it’s the state most analyses actually live in.

You don’t need to keep up with everything I type. Every code block has a copy button, and anything extra I write on the day goes up on GitHub.

The boxes

Five kinds of box turn up, each with its own colour and icon:

  • ✏️ Your Turn - something for you to do. Most we do together. The ones that ask what you think have no wrong answers.
  • 🕰️ Some history - where an idea came from.
  • 🔎 Going deeper - optional detail, a longer example, or a pointer to the paper. Boxes titled Read more point at the post or talk a section is adapted from.
  • ⚠️ Watch out - a place people commonly trip.
  • 🚨 - the things that will bite you.
NoteYour Turn

Exercises look like this. Most give you something to run:

R.version.string

Some just ask you something. Here is the one I care about:

  1. Think of the last analysis you had to re-run from scratch. What made you do it?
ImportantRestart R after a big install

If you install a package that is already loaded, R can end up half on the old version and half on the new one. You then get errors that make no sense and do not survive a restart.

So once you have worked through the installs below, restart R.

  • Ctrl + Shift + F10 on Windows
  • Cmd + Shift + 0 on Mac

The code

Lines starting with #> are output, not code. You don’t type those.

We use the base pipe, |>, throughout, rather than %>%. If you’re used to %>%, everything here works the same way.

What to install

R

You need R 4.5.0 or later, from https://cran.r-project.org/. Check with:

R.version.string

You also need an editor. I recommend RStudio, and Positron works too.

The R packages

This will take a few minutes.

They are grouped by what they are for, rather than alphabetically, so you can see what you are installing.

# the analysis itself
install.packages(c(
  "arrow",      # reads the parquet data files
  "broom",      # turns a model into a data frame
  "conflicted", # makes function masking an error rather than a surprise
  "here",       # file paths that work from anywhere in a project
  "janitor",    # clean_names(), and other tidying
  "tidyverse"   # dplyr, ggplot2, readr, lubridate and friends
))

# making pictures
install.packages(c(
  "gganimate",  # the march of the cane toads
  "gifski",     # renders the animation to a gif
  "leaflet",    # interactive maps
  "ozmaps",     # Australian state boundaries to draw the toads on
  "visdat"      # vis_dat(), for seeing what is missing
))

# pipelines
install.packages(c(
  "crew",       # parallel workers
  "fs",         # file and directory handling
  "quarto",     # rendering reports from the pipeline
  "tarchetypes",
  "targets",
  "visNetwork"  # what tar_visnetwork() draws the graph with
))

# spatial, for the last three hours
install.packages(c("geotargets", "sf", "terra"))

{visNetwork} is what draws the dependency graph when you run tar_visnetwork(), which we use constantly, and it is not a dependency of targets.

{sf} and {terra} are only needed at the end, but they are the slowest to install, so it is worth doing now rather than on the day.

WarningWatch out: sf and terra need system libraries

On Mac and Linux these two build against GDAL, GEOS and PROJ. If install.packages("sf") fails with something about a missing header, that’s why.

On Mac, brew install gdal usually sorts it. On Ubuntu, the libgdal-dev package. On Windows the binaries come with everything included and it just works.

Please email me if you hit this before the day, because it is much easier to fix with two people looking at it.

Installing {tflow} and {fnmate}

Two of Miles McBain’s packages that make pipelines much less tedious. {tflow} sets a project up, and {fnmate} writes the skeleton of a function from a call you wish you could make.

Neither is on CRAN. They live on Miles’ r-universe, which is an ordinary website that R installs from, so there is no git and no compiler involved:

install.packages(
  c("tflow", "fnmate"),
  repos = c(
    "https://milesmcbain.r-universe.dev",
    "https://cloud.r-project.org"
  )
)
ImportantIt’s OK if these don’t install

Some machines will not install from anywhere except CRAN, and if yours is one of them, that’s a setting somebody else chose and not a problem with you.

Nothing in this course depends on either package. They save typing. Everywhere I use one, I will also show what it wrote, so you can type the same thing yourself.

Checking it all worked

pkgs <- c(
  "arrow", "broom", "conflicted", "crew", "fs", "geotargets", "gganimate",
  "gifski", "here", "janitor", "leaflet", "ozmaps", "quarto", "sf",
  "tarchetypes", "targets", "terra", "tidyverse", "visdat", "visNetwork"
)

Everything should come back TRUE.

The course data and the analysis

We work on cane toad occurrence records from the Atlas of Living Australia, plus eleven other species we meet later.

The analysis lives in its own repository, toad-analysis. This code from usethis downloads it and opens it as an RStudio project:

usethis::use_course("njtierney/toad-analysis")

If that doesn’t work on your machine, the same files are in this zip — clicking the link should download it: https://github.com/njtierney/toad-analysis/archive/refs/heads/main.zip

Unzip it, and open toad-analysis as an RStudio project. It looks like this:

toad-analysis/
├── data/
│   ├── cane-toad-wildnet-to-1999.parquet
│   ├── cane-toad-wildnet-to-2010.parquet
│   ├── cane-toad-wildnet.parquet
│   ├── cane-toad-all.parquet
│   └── ...
├── ch1/
│   └── 01-flat-script.R
├── ch2/
│   ├── R/
│   ├── analysis.R
│   └── toad-report.qmd
└── ...

There is one folder for each chapter, and each is the same analysis a little further along. The data is shared between all of them.

Nine data files, because chapter 1 is about what happens when more data arrives. You start with the Queensland records up to 1999 and change the filename when the rest turns up — first more years, then more sources.

That is a working analysis, and it is yours.

Run it, read it, break it, improve it.

We spend the whole course changing it, and by the end it will be a pipeline.

The data is parquet rather than CSV, which is why it is small enough to hand out.

arrow::read_parquet() reads one and gives you back an ordinary data frame.

TipGoing deeper: where the data came from

data-raw/01-download-occurrences.R in the book’s repo is the script that made these files. It uses galah to query the Atlas of Living Australia.

You do not need to run it, and I would rather you didn’t on the day, because thirty people hitting the same API at once is not a good time for anybody. But it is there, it is commented, and it’s a reasonable model for the kind of script that belongs in data-raw/.

Records under a non-commercial licence have been removed, so what you have is a little smaller than what the Atlas will give you.

What to bring

An analysis of your own.

Something with more than one step. Something where you have caught yourself re-running the whole thing because you were not sure what was still current. It doesn’t need to be tidy, and it’s more useful to me if it isn’t.

We convert your own work in the final session, and you will get more from that hour than from any example I could invent, because you already care about the answer.

If you’d rather not share your own, that’s completely fine. I have one for us to work on either way.
